# KHL Reels

Каждый день в **7:00 по Москве** проект автоматически публикует в Instagram **пост-карусель из двух картинок**: турнирные таблицы конференций «Запад» и «Восток» КХЛ (Континентальная хоккейная лига). В подписи к посту короткий разбор от ИИ.

Вечером, после последнего матча дня, выходит **Reels «Итоги игрового дня»**: обзор каждого сыгранного матча. От ИИ-аватара отказались.

## Reels «Итоги игрового дня»
- Сцены: заставка → по сцене на матч → финал. Сцена матча: разделённый по диагонали экран (сверху хозяева, снизу гости, цвета клубов, логотипы, счёт, как в образце @sportonkp) → лента голов (время, автор, номер гола в сезоне, ассистенты, БОЛ/МЕН/П.В., победный буллит) → положение обеих команд в таблице. Субтитры по всему ролику.
- Только моушн-графика: **фото с матчей не используем** (авторские права, решение пользователя).
- Голос: **Яндекс SpeechKit** API v3, выбран пользователем `ermil` + `good` + скорость 1.2 (2026-10-18, было 1.1; остальные голоса Яндекса, включая LiveTTS, не понравились). Настройки и ключ в `.env`: `YANDEX_API_KEY`, `YANDEX_VOICE`, `YANDEX_ROLE`, `YANDEX_SPEED` (`YANDEX_MODEL=livetts` для vasily/sergey/denis, у них нет скорости). Код: `scripts/tts-yandex.mjs` (IPv4 первым: по IPv6 соединение обрывается). Если какая-то сцена не озвучилась за 5 попыток, ролик не собирается.
- Музыка: трек пользователя (Macan feat. Yasmi — Jet) в `video/public/music/track.mp3`, не в Git. Для сервера лежит в приватном GitHub Release `assets` (заменить: `gh release upload assets track.mp3 --clobber`). Пользователь предупреждён о риске авторских прав и решил использовать. Громкость 0,09 под голосом и 0,25 в паузах, плавное приглушение (`video/src/review/ReviewVideo.tsx`, константы `MUSIC_*`).
- Текст озвучки: `scripts/review-script.mjs` (шаблон в настоящем времени, чтобы не склонять названия команд; с `ANTHROPIC_API_KEY` пишет Claude через structured output).
- Компоненты: `video/src/review/` (`Intro`, `MatchScene`, `Outro`, `Subtitles`, `ReviewVideo`), цвета клубов: `video/src/clubColors.ts`.
- Источники: календарь `POST /rest/calendar/list/` (весь сезон; у матча `time_format` по МСК, `isOnline` значит идёт, счёт и `ots` = OT/SO у завершённых), протокол `POST /rest/game/protocol/` с `values[tournament]=1436` и `values[gameid]` (голы по периодам; победный буллит = «гол» 4-го периода на 65:00).
- Вечерний запуск НЕ пишет снимок таблицы в `data/history/`: снимок дня делает только утренняя карусель. Вечерний воркфлоу ставит свою метку: `data/reviews/ГГГГ-ММ-ДД.json` (копия `review.json`), значит, ролик за этот день уже отправлен.

## Пользователь
- Общается на русском, отвечать по-русски, просто и по шагам.
- Часто диктует голосом, поэтому в тексте бывают оговорки. Понимать по смыслу.
- Windows 11, PowerShell, VS Code на русском. Опыт программирования небольшой: объяснять, что и зачем делаем.
- **Сначала план, действия только после его согласия.** Ничего не запускать и не устанавливать без спроса.

## Конвейер
1. **Данные**: свежая таблица с khl.ru, скрипт `scripts/fetch-standings.mjs` пишет её в `video/public/standings.json`.
2. **Картинки**: две картинки 4:5 (1080×1350), «Запад» и «Восток». Рисуем в **Remotion** (`<Still>`) с логотипами клубов. Запад светлый («лёд днём»), Восток тёмный с янтарным акцентом («ночь»).
3. **Подпись**: вчерашние матчи, кто поднялся и кто опустился (сравнение со вчерашним снимком в `data/history/`), лидеры, борьба за 8-е место, хэштеги. С `ANTHROPIC_API_KEY` в `.env` текст пишет Claude (`claude-opus-5-5`, включены серверные fallbacks), без ключа собирается по шаблону.
4. **Одобрение**: бот @khltable_bot присылает пользователю картинки и подпись с кнопками «Опубликовать / Отмена».
5. **Публикация**: карусель через Instagram Graph API.
6. **Расписание**: GitHub Actions `.github/workflows/morning-cards.yml` («Карусель 7:00»), cron `45 3 * * *` = 6:45 МСК (раньше 7:00, потому что расписание GitHub опаздывает).
7. **Два будильника** (2026-10-18): расписание GitHub в первый вечер пропустило все проверки, поэтому воркфлоу дополнительно запускает **cron-job.org** (аккаунт пользователя) через `workflow_dispatch`: «KHL: Карусель 6:45» и «KHL: Итоги дня» (20–01 ч МСК, минуты 10/30/50). Задания создаёт и обновляет `node scripts/setup-cronjobs.mjs` (`--list` показывает статус). Ключи в `.env`: `CRONJOB_API_KEY` и `GH_DISPATCH_TOKEN` (fine-grained токен GitHub: только khl-reels, Actions: Read and write). В GitHub Secrets они не нужны. **Токен истекает 2027-01-16**: заранее напомнить пользователю, продлить (Regenerate), заменить в `.env` и перезапустить `setup-cronjobs.mjs`. Дубли отсекают метки: утро `data/cards/ГГГГ-ММ-ДД`, вечер `data/reviews/ГГГГ-ММ-ДД.json`; оба воркфлоу делают checkout свежего `main`.

## Команды
- `npm run cards` (= `node scripts/make-cards.mjs`) выполняет весь цикл: таблица и логотипы → `video/out/west.jpg`, `east.jpg`, `post.txt` → альбом и текст в Telegram.
- `npm run standings` только забирает данные, печатает таблицу и пишет снимок дня.
- `node scripts/make-review.mjs [ГГГГ-ММ-ДД] [--partial] [--no-send]` собирает Reels «Итоги дня» → `video/out/review.mp4`, `review-caption.txt` → Telegram. Без `--partial` ждёт, пока закончатся все матчи дня.
- `node scripts/fetch-games.mjs [ГГГГ-ММ-ДД]` печатает матчи дня с голами и положением команд.
- `node scripts/review-status.mjs ГГГГ-ММ-ДД` быстро проверяет по календарю, сколько матчей дня закончилось (для вечернего воркфлоу).
- Общие запросы к khl.ru (обход защиты, сессия, REST): `scripts/khl.mjs`.
- `cd video` и `npm run dev` открывают студию Remotion для правки дизайна (композиции `west`, `east`).
- Дизайн карточки: `video/src/StandingsCard.tsx`, палитры: `video/src/themes.ts`. Шрифт Manrope. Текст поста: `scripts/post-text.mjs`.
- Логотипы скачиваются в `video/public/logos/{clubId}.png` (не в Git). На img.khl.ru та же защита от ботов (307 + cookie), что и на сайте.
- Снимки таблицы `data/history/ГГГГ-ММ-ДД.json` хранятся в Git: без вчерашнего снимка блок «поднялись / опустились» пропускается.

## Источник данных (khl.ru)
- Сначала `GET https://www.khl.ru/standings/` с браузерным User-Agent. Защита от ботов отвечает 307 и ставит cookie `spid`/`spsc`, после повтора с cookie отдаёт страницу. Из HTML берём `"bitrix_sessid":"..."`.
- Затем `POST https://www.khl.ru/rest/standings/regular/` (form-data `values[type]=regular`, `sessid`; заголовки Cookie, Referer, `X-Requested-With: XMLHttpRequest`).
- Ответ: `{status:"success", data:{json:{conferences:[{item:"west"|"east", rows:[...]}], league, divisions}}}`. По 11 команд в конференции, строка `{"type":"divider"}` означает линию плей-офф (после 8-го места).
- Поля команды: `r` (место), `name`, `clubid`, `s{gp,w,otw,sow,sol,otl,otl_en,l,pts,g:"50-27"}`, `live.position{old,new}`, `team_last_matches` (JSON-строкой), `team_next_match`.

## Ограничения
- Для Instagram Graph API нужен Business- или Creator-аккаунт, привязанный к странице Facebook, и приложение в Meta for Developers. Картинки для карусели должны лежать по публичному URL, формат JPEG.
- Логотипы клубов используем по решению пользователя (2026-10-17), хотя это товарные знаки: есть небольшой риск жалобы правообладателя в Instagram. Фото игроков не берём.
- Instagram заблокирован в РФ, поэтому сервер для публикации лучше держать за рубежом.
- Защита khl.ru пускает серверы GitHub Actions (проверено 2026-10-18 с сервера в США: таблица, логотипы и рендер работают).
