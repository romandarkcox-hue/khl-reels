# KHL Reels

Проект публикует в **Telegram-канал [@KHLtablitca](https://t.me/KHLtablitca)** («Турнирная таблица КХЛ | сезон 2026/27»; с 2026-10-23, до этого был @KHLtable, его оставили как есть) посты про КХЛ (Континентальная хоккейная лига). Формат утверждён пользователем 2026-10-22 (до этого была пауза с 21.10, а ещё раньше Instagram и Reels):

- **Утро, 7:00 МСК: анонс.** Картинка «Матчи дня»: время начала (МСК), команды с логотипами, место каждой в таблице конференции. Больше 6 матчей → две картинки. Нет матчей → ничего не публикуем. Подпись: список матчей + хэштеги.
- **Вечер, после последнего матча: два отдельных поста** (пользователь 22.10: не смешивать в одном альбоме):
  1. картинка «Итоги дня» со счетами (ОТ/Б) + подпись: по каждому матчу счёт, победитель и короткая фраза из протокола (победный гол/буллит, камбэк, дубль/хет-трик, сухая победа, разгром) + хэштеги. Пользователь просил **не писать очевидное** (вверх/вниз в таблице, лидеры, борьба за 8-е место убраны);
  2. таблицы «Запад» и «Восток» альбомом + короткая подпись «Таблица КХЛ после игрового дня …» (`tablesText`).
  Пост ждёт, пока заполнятся протоколы всех матчей (сразу после сирены протокол на khl.ru пустой, заполняется примерно в течение получаса); к последней проверке ночью выходит как есть.
- Публикуем **сразу, без кнопок одобрения** (выбор пользователя).
- **Те же посты дублируются в группу ВК [vk.ru/khltable](https://vk.ru/khltable)** («Турнирная таблица КХЛ 2026/2027», id 232858456; подключено 2026-10-28): сразу после Telegram, только при публикации в канал. Те же тексты; картинки **с 2026-11-10 обычными фото, все в одной записи** — ключом пользователя-админа `VK_USER_TOKEN` (тот же, что у канала «Доброе утро»; получен через oauth.vk.com, client_id 2685278, права wall,photos,groups,offline, бессрочный). Если фото не загрузились за 5 попыток — запасной способ гифками с `VK_GROUP_TOKEN` (как было с 28.10), потом только текст. Не вышло с гифками → текст + строка «🖼 Картинки — в Telegram: ссылка на пост» и предупреждение в личку. Ключ пользователя VK ID больше не нужен (был запасным планом). Аватарка и обложка группы: композиции `vk-avatar-a/b`, `vk-cover`, слайды истории `vk-story-1/2/3` (`video/src/BrandCards.tsx`), без логотипа КХЛ.

## Второй канал: «ПРОГНОЗЫ КХЛ | HITRATE AI» (с 2026-11-16)
- Канал **[@prognozykkhl](https://t.me/prognozykkhl)**, свой бот **@khl_hitrate_bot** (`.env`/Secrets: `HITRATE_BOT_TOKEN`, `HITRATE_CHANNEL_ID`). Первый пост — прогноз на 16.11 (пост 6). ВК не дублируем.
- **Утро 9:00 МСК** (`.github/workflows/hitrate-predict.yml` + задание cron-job.org «KHL: Прогноз 9:00»): `node scripts/hitrate.mjs predict [ДЕНЬ] [--to-me | --no-send]` — картинка `predict` + подпись. Начавшиеся матчи не прогнозируем. Прогноз пишется в журнал `data/predictions/ДЕНЬ.json` **до** отправки и не перезаписывается (честный HitRate); файл журнала — метка «опубликовано».
- **Вечер**: шаг «Проверка прогнозов HitRate» в `evening-review.yml` (после основного поста, `continue-on-error`): `node scripts/hitrate.mjs check ДЕНЬ` — счета, ✅/❌, `checkedAt` в журнале, картинка `check`.
- **Модель** (`scripts/predict.mjs`): Эло только по результатам матчей khl.ru, **без коэффициентов БК** (бесплатного API с КХЛ нет). Прошлый сезон — турнир 1369 (`calendar/list` с `values[tournament]`), рейтинг переносится наполовину. K=14, дом +15, поправка на разницу шайб, победа в ОТ/Б = 0.75. Проверка 16.11: 56% всех матчей, ~65% «уверенных» (фаворит ≥ 60%). HitRate канала = доля угаданных уверенных прогнозов по журналу.
- Картинки `video/src/PredictCard.tsx` (графит + золото), аватарки `hitrate-avatar-a/b` (`video/src/HitrateAvatar.tsx`). В подписи строка «Прогноз — расчёт модели по статистике, а не совет делать ставки» (закон о рекламе ставок): коэффициенты и букмекеров не упоминаем.
- `hitrate-env.mjs` подменяет `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHANNEL_ID` перед загрузкой `send-telegram.mjs`; `--to-me` шлёт в личку от нового бота.

## Код
- `scripts/make-announce.mjs [ДЕНЬ] [--to-me | --no-send]` — утренний анонс. По умолчанию публикует в канал; `--to-me` шлёт в личку пользователю, `--no-send` только рисует.
- `scripts/make-evening.mjs [ДЕНЬ] [--partial] [--to-me | --no-send]` — два вечерних поста. Без `--partial` выходит без публикации, если не все матчи закончились или протоколы не заполнены; после публикации в канал создаёт `video/out/evening-posted`, по нему воркфлоу ставит метку дня. Снимок таблицы `data/history/ДЕНЬ.json` пишется **только при публикации в канал** (пробные запуски его не трогают), под датой игрового дня.
- `scripts/day-cards.mjs` — общий код: матчи дня из календаря (+ голы из протокола при `withGoals`) и рендер картинок `announce-N` / `results-N`. Проверка: `node scripts/day-cards.mjs announce|results [ДЕНЬ]`.
- **Один SEO-текст для Telegram и ВК (одобрено 05.11):** первая строка с поисковыми словами и датой («🏒 Матчи КХЛ сегодня, 5 ноября: расписание», «🏒 Результаты КХЛ 4 ноября: <самый яркий матч>», «📊 Турнирная таблица КХЛ после матчей 4 ноября»); клубы полностью с городом и хэштеги клубов дня из `scripts/clubs.mjs` (новый клуб в лиге → дописать туда); строка `CHANNEL_LINE` со ссылкой на канал; хэштеги #КХЛ #хоккей + #расписаниеКХЛ / #результатыКХЛ / #таблицаКХЛ. Анонс: каждый матч блоком, места строкой ниже; если подпись длиннее 1024 знаков — места в скобки, потом без городов. Итоги: сокращаются описания, потом города.
- **Первая строка поста = заголовок** (её видно в списке чатов Telegram; правило из навыка `social`, утверждено 2026-10-29). Утро (`headline` в `make-announce.mjs`): «🏒 Сегодня в КХЛ N матчей, главный: A (2-е) — B (9-е) · дата», главный = наименьшая сумма мест. Вечер (`headline` в `post-text.mjs`): два самых ярких матча (разгром > камбэк > хет-трик > сухая > ОТ/Б > обычная) с глаголом в нужном роде (`GENDER`, `ACCUSATIVE` — при новой команде с женским/средним родом или склоняемым именем дописать), повтор глагола заменяется синонимом.
- `scripts/post-text.mjs` — подпись вечернего поста (шаблон; с `ANTHROPIC_API_KEY` пишет Claude). Подпись ≤ 1024 знаков (лимит Telegram), при превышении описания матчей сокращаются; `sendPost` в `send-telegram.mjs` всё равно отправит длинный текст отдельным сообщением.
- `scripts/send-telegram.mjs` — `sendPost(файлы, текст, чат)`: одна картинка или альбом с подписью; возвращает ссылку `t.me/…/N` на пост (для публичного `@канала`). Канал — `TELEGRAM_CHANNEL_ID=@KHLtablitca`, личка — `TELEGRAM_CHAT_ID`.
- `scripts/send-vk.mjs` — **основной путь с 10.11:** `sendVkPhotoPost(файлы, текст)` с `VK_USER_TOKEN`: `photos.getWallUploadServer` → загрузка → `photos.saveWallPhoto` → одна запись `wall.post` с фото (до 10). Сервер загрузки иногда отвечает 500 или пустым `photo` — до 5 попыток. Номер группы `VK_GROUP_ID` (по умолчанию 232858456). Проверка: `node scripts/send-vk.mjs a.jpg b.jpg --text-file … --delayed` (отложенная запись через 30 дней). Отложенные записи через API удалить нельзя (ошибка 210) — только вручную. Если ключ пользователя отозвали или сменили пароль ВК — получить заново и обновить `.env` + `gh secret set VK_USER_TOKEN`.
- **Сбой 12–15.11:** ключ пользователя получил `9 Flood control` на все методы API (даже `users.get`), новый ключ через oauth — тоже: ограничена учётная запись, вручную в ВК всё работает. Запасной путь тогда тоже молчал, т.к. `wallPost` по умолчанию брал ключ пользователя — исправлено: гифки и текст публикуются `VK_GROUP_TOKEN`, при ошибке 9 повторов нет. Тем же ВК-аккаунтом, возможно, пользуется проект fan-reels. Проверка запрета: `users.get` с `VK_USER_TOKEN`.
- Запасной путь (гифки): `sendVkPost(файлы, текст)` на стену группы ВК (`wall.post`, `from_group=1`): каждая картинка → GIF (`npx remotion ffmpeg` с палитрой под картинку, рядом с исходником) → `docs.getWallUploadServer` + `docs.save` → вложение `doc…`. **В одной записи ВК допускает только одну гифку** (две → «Exceeded max amount of doc attachments», вечер 28.10), поэтому каждая картинка идёт отдельной записью; публикуем с конца, так что наверху стены запись с текстом и первой картинкой. Гифку без текста ВК не принимает («Required any of text…»): у остальных записей подпись — первая строка текста + «(2/2)». Удалять записи (`wall.delete`) ключ сообщества не может (ошибка 27), только вручную. Загрузка гифки (`uploadDoc`) повторяется до 3 раз с паузой 5 с: сервер загрузки ВК бывает отвечает страницей ошибки вместо JSON (утро 30.10). **Превью гифки ВК готовит не сразу** (в ответе `docs.save` оно 0×0, через 1–5 с появляется): запись, опубликованная раньше, навсегда остаётся просто файлом «west.gif» без картинки (так и были «случайные» сбои до 05.11). Поэтому после `docs.save` бот ждёт превью через `docs.getById` (ключ сообщества это может; `docs.get`, `wall.getById` — нет) до 60 с, иначе загружает заново (копия с GIF-комментарием, чтобы файл был новым). Гифка из двух кадров не годится: ВК делает из неё видео и ломает превью (опыт 05.11). `sendVkPostSafe(файлы, текст, ссылкаTelegram)` для утра и вечера: не вышло с гифками за 3 попытки → текст со ссылкой на Telegram; ошибки не роняют запуск, а приходят пользователю в личку Telegram; без `VK_GROUP_TOKEN` ВК пропускается. Ссылку на пост даёт `sendPost` из `send-telegram.mjs`. Ключ сообщества `VK_GROUP_TOKEN` (не истекает; права: стена, фото, управление, файлы; в группе должен быть включён раздел «Файлы»). **Проверено 2026-10-28:** `photos.getWallUploadServer`/`getUploadServer` → ошибка 27; «фото для сообщений» (`getMessagesUploadServer` + `saveMessagesPhoto`) и jpg-файл загружаются, но `wall.post` молча их выбрасывает; ссылка во вложении → ошибка `link_photo_sizing_rule`; `video.save` → только ключ пользователя. **GIF-файл проходит.** Читать стену (`wall.get`, `wall.getById`) ключ не может, поэтому вид поста проверяет пользователь: пробовать **отложенной записью** (`publish_date` через месяц), её видят только администраторы. Расширенный доступ `photos` для ключа пользователя VK ID по документации даёт только после подтверждения бизнеса и заявки в devsupport@corp.vk.com. API `https://api.vk.ru`, v 5.199.
- `scripts/env.mjs` — грузит `.env` **поверх** переменных Windows: у пользователя в Windows задана своя `TELEGRAM_BOT_TOKEN` от другого бота (@alinasokol_bot), из-за неё раньше локальные запуски слали не от того бота. Все скрипты импортируют `./env.mjs`.
- Картинки: `video/src/AnnounceCard.tsx` (анонс и счета, тёмно-синий «вечерний лёд», при 1–2 матчах крупные строки), `video/src/StandingsCard.tsx` (таблицы), палитры таблиц `video/src/themes.ts`, цвета клубов `video/src/clubColors.ts`. Шрифт Manrope. Композиции: `announce-1/2`, `results-1/2`, `west`, `east`.
- `scripts/khl.mjs`: `gameStatus` считает матч завершённым и по `g.online.status = "Завершен"` (сразу после сирены, пока протокол не утверждён, счёт лежит в `g.online`), `gameScore(g)` берёт счёт оттуда же.
- `scripts/review-status.mjs ДЕНЬ` — сколько матчей дня закончилось (для вечернего воркфлоу).

## Расписание (GitHub Actions + cron-job.org)
- `.github/workflows/morning-cards.yml` («Анонс 7:00»): cron `0 4 * * *` = 7:00 МСК → `make-announce.mjs` → метка `data/posted/ДЕНЬ-announce`.
- `.github/workflows/evening-review.yml` («Итоги дня»): каждые 20 мин с 20:30 до 01:10 МСК; игровой день = МСК минус 5 ч; метка `data/posted/ДЕНЬ-evening` → выход; все матчи закончились → `make-evening.mjs`, коммит метки и `data/history/`; после 01:00 МСК публикует с `--partial`. Ручной запуск с полями day / partial / force.
- **Автоматика включена 2026-10-22** (воркфлоу `gh workflow enable`, задания cron-job.org `enabled: true`, секрет `TELEGRAM_CHANNEL_ID`). Сменить канал: бот администратором нового канала, новое значение в `.env` и `gh secret set TELEGRAM_CHANNEL_ID`.. Выключить: `gh workflow disable morning-cards.yml` и `evening-review.yml` + задания на cron-job.org. Имена файлов воркфлоу прежние (раньше там были карусель и Reels).
- **cron-job.org** дублирует запуски через `workflow_dispatch` (расписание GitHub пропускает и опаздывает): «KHL: Анонс 7:00» (раньше «KHL: Карусель 6:45», скрипт находит его по старому имени) и «KHL: Итоги дня» (20–01 ч МСК, минуты 10/30/50). `node scripts/setup-cronjobs.mjs` создаёт/обновляет (ставит `enabled: true`), `--list` показывает статус. Ключи в `.env`: `CRONJOB_API_KEY`, `GH_DISPATCH_TOKEN` (fine-grained, только khl-reels, Actions: Read and write). **Токен истекает 2027-01-16**: заранее напомнить, продлить (Regenerate), заменить в `.env`, перезапустить `setup-cronjobs.mjs`.
- В GitHub Secrets нужны `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_CHANNEL_ID`, `VK_GROUP_TOKEN`, `VK_USER_TOKEN` (+ `ANTHROPIC_API_KEY`, если появится). Новый ключ в `.env` → загрузить: `gh secret set ИМЯ`.
- Перед ручной работой с `data/` делать `git pull`: бот коммитит в main утром и вечером.
- Стоимость: всё бесплатно (лимит GitHub Actions 2000 мин/мес, расход ~1100–1200).

## Источник данных (khl.ru)
- Сначала `GET https://www.khl.ru/standings/` (или `/calendar/`) с браузерным User-Agent. Защита от ботов отвечает 307 и ставит cookie `spid`/`spsc`, после повтора с cookie отдаёт страницу. Из HTML берём `"bitrix_sessid":"..."`. Общий код: `scripts/khl.mjs`.
- Таблица: `POST /rest/standings/regular/` (form-data `values[type]=regular`, `sessid`; заголовки Cookie, Referer, `X-Requested-With: XMLHttpRequest`). Ответ: `data.json.conferences[{item:"west"|"east", rows}]`, по 11 команд, `{"type":"divider"}` = линия плей-офф. Поля: `r`, `name`, `clubid`, `s{gp,w,otw,sow,sol,otl,l,pts,g}`, `live.position{old,new}`.
- Календарь: `POST /rest/calendar/list/` (весь сезон, `GAMES[]` по дням, `TEAMS`, `time_format` по МСК; у утверждённых матчей `homeScore`/`visitorScore`/`ots`, у только что закончившихся счёт в `online`; `isOnline` = идёт). За сезон 1–8 матчей в день (8 — дважды).
- Протокол: `POST /rest/game/protocol/` с `values[tournament]=1436` и `values[gameid]` (голы по периодам; победный буллит = «гол» 4-го периода на 65:00). Разбор: `parseGoals` в `scripts/fetch-games.mjs`.
- Логотипы `video/public/logos/{clubId}.png` (не в Git), img.khl.ru за той же защитой. Логотипы используем по решению пользователя (риск жалобы правообладателя объяснён). Фото игроков не берём.
- Защита khl.ru пускает серверы GitHub Actions.
